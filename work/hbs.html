The role

Builder first, enabler second

The title says enablement, and part of the job is exactly that: workshops, onboarding, and helping teams figure out where AI actually saves time. Most of my week goes to building. Someone brings a problem to IT intake, I scope it, decide whether it needs an agent, a workflow, or just a better prompt, and then I build it, test it, and stay with it after it ships.

I work across the Microsoft stack (Copilot, Copilot Studio, Power Automate, SharePoint, Teams, Microsoft Graph), plus Rewst and ConnectWise on the service-desk side and Anthropic's Claude when it's the better tool for the job.

What I've built

Agents in production

HBS Assist: IT intake in Teams

A Copilot Studio agent where employees describe an IT problem in their own words. It asks a few follow-up questions, reads back a summary to confirm, then creates the ticket and routes it to the right team. It sticks to intake: it never asks for passwords and doesn't try to troubleshoot, and security issues go in as high priority. Behind it, the agent sends one structured payload to Rewst workflows that open the ConnectWise ticket. Screenshots and documents attach straight to the ticket, and if a submission fails, it falls back to the triage inbox. I own the agent end to end.

Licensing Advisor: keeping expert knowledge usable

Our Microsoft licensing knowledge lived mostly in one senior specialist's head. I built a pipeline that captures it. Scheduled tasks archive her client call transcripts to SharePoint each week. A second task pulls out what the client had, what she recommended, and why. A third adds that to a five-document knowledge base, and every change goes into a review log. A Copilot Studio agent answers the team's licensing questions from those documents only, names its source, dates every price it quotes, and shows both sides when past calls disagreed instead of guessing.

HBS Navigator: "who do I go to?"

A routing agent for our Managed Services team, which gets a lot of requests meant for other departments. I researched 57 internal routing topics from our intranet, covering owning team, intake method and source page, and put them in a list the team can edit. Answers cite the intranet page and flag anything more than a year old. A read-only Rewst lookup returns a client's account team from ConnectWise. New IT issues get handed to HBS Assist so the two agents never overlap. It passed a 35-case test plan before launch.

Field Friction Signal: sales feedback leaders can act on

A form and a Teams agent where sellers in one sales region report recurring friction with internal processes. AI puts each report into one of ten categories, writes a short theme, and separates one-off escalations from patterns. Critical reports message the seller's manager right away. A second, leaders-only agent answers questions like "what are the top issues this quarter?" with real quotes, and sends each leader a Monday digest. It's built on Copilot Studio, Power Automate and a SharePoint list, and sellers see only their own reports.

HBS Cowork

Building and rolling out our own AI workspace

HBS Cowork is HBS's own desktop AI workspace, connected to the Microsoft 365 data people already work in (email, Teams, SharePoint and OneDrive). I help build, test and design it, and I run much of the rollout: an onboarding course, one-on-one setup, and digging through failed sessions and Graph permission errors to fix what blocks people.

I've also written Cowork skills, packaged instructions with reference material, for our Dynamics 365 practice. They cover discovery, requirements, fit-to-standard analysis, health checks, solution design and statements of work. Each skill includes licensing guidance, so every SOW it helps produce comes with licensing recommendations.

How I build

Rules every agent follows

  • Tight scope. Each agent does one job and politely declines the rest. Intake agents don't troubleshoot, and routing agents don't guess.
  • Cite the source or say you don't know. Knowledge agents answer only from approved documents, name the one they used, and send people to a human when the answer isn't there.
  • Additive, reviewable updates. Automated knowledge updates only add entries, log every change, and leave anything uncertain for a person to review.
  • Agents hand off, not overlap. When a request belongs to another agent, it passes the user along instead of half-answering.
  • Tested before shared. Written test plans, tool tests and a review against Microsoft's Copilot Studio guidance before anything leaves a pilot group.
